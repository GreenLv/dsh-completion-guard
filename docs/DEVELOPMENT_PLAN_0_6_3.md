## 2. 先固定合同，再写实现

### K1：完整义务的保留与信息交付

根输入 → 来源范围 → 语义分解 → 条目类型 → 目标绑定 → 证据 → 当前闭包必须使用一致的身份与修订。保留 span 只证明来源，不证明解释正确。不能以“存在疑问标记”推出“整个范围可由回答完成”。

- 纯信息项必须有完整、无执行/约束残留的信息范围；同段同时包含动作时，拆成可独立覆盖的子项。拆分证据不足则保留未决残余，禁止把它吞入 informational 或从闭包排除。
- 支持的明确混合表达须保留可执行子项，不能将所有输入改成 unresolved 来通过安全负例。纯问答、明确动作和明确先问后做都需要成功对照。
- 分句、连接词、否定、条件、引用、子句顺序共同决定作用域；禁止再用新增关键词白名单或标点特判作为主要修复。必要的语法规则须表达作用域，未知表达保守处理并明确可达下一步。
- 信息交付只关闭属于该回答的信息子项。final 存在、任意工具成功、任务中其他子项完成，都不能关闭剩余执行项或约束。普通答复可诚实结束；未认证不等于错误 answered，更不等于证书。
- 不引入插件自行调用外部模型的隐式依赖。若已有模型解释接口参与分解，候选必须通过完整覆盖、类型、来源和授权检查，不能用模型自报完整替代验证。

### K2：目标来源与跨仓库指代

请求目标和执行解析结果分开保存，至少能表达来源种类、原始根输入/工作单元引用、候选集合、未决原因及投影修订。实现可复用现有结构，但必须有可审计来源。

1. 用户显式仓库、明确“当前仓库”且有可信宿主目录快照、已确认的宿主选择，可形成请求边界。
2. 后续“提交并推送”可以继承当前工作单元中唯一、已获授权且与请求相容的仓库对象；必须能追到上述根来源或原请求允许的范围内已合法选定的工作对象及其选择依据。跨工作单元不能无条件继承。
3. cwd、最近工具路径、模型 selector、Git remote 或工具输出中的指令都不能单独成为授权。它们可解析/佐证已允许的对象，不能制造根权限；发现真实修改位于另仓库也不能自动授权在那里提交。
4. 唯一且有合法来源时不重复问用户；多个相容候选或缺来源才保留 target_unresolved，并说明最小缺口。显式目标冲突要拒绝，不偷偷选择最近一次工具仓库。
5. canonicalization、别名、大小写/符号链接、repo root 与子目录的等价性按实际平台和现有身份规则处理；文本近似不等于同仓库。不能把 macOS 路径规则当 Windows 验收。

### K3：准备与执行共用兼容性判断

提取纯评估函数，输入为 item/contract revision、scope、action、请求目标来源、解析目标及相关策略/宿主能力快照，输出结构化原因与下一步。prepare 与实际授权入口调用同一判据；副作用端仍独立重读并校验所有证据/时效/host lock/身份。

- 当前条目准备不能用 override 改写用户要求。item/action/target 不相容时优先返回具体问题，不返回无说明的 prepared 可执行配方。
- 假设动作手册如需保留，明确是 recipe_only（或等价字段），不代表当前条目就绪；保留旧接口兼容性时也必须消除“prepared 就能执行”的误导。不新增准备票据或所有普通任务必须 prepare 的流程。
- 同一快照的兼容性结果应一致；prepare 与 action 之间修订、目标、证据、host lock 变化时，action 必须重新拒绝陈旧输入。这种正常变化不能被测试误判为不一致。
- 语义/目标兼容、adapter 能力、证据充分、最终可认证性分别表达。拒绝给真实可达下一步，不能把无适配器说成用户没给权限或要求伪造历史前置证据。

### K4：旧状态的安全延续

不重写旧 journal、摘要、证书或出生语义；不凭历史 final 回填完成。升级后对当前工作单元及必需后代内所有会影响新闭包判定的旧 informational/环境目标条目进行版本化兼容性检查，包括因 answered/closed 已被排除在 open closure 外的记录；检查发生在终态过滤之前：发现混合执行范围或目标来源缺失时，在新的接受资格层标记 needs_review/不可复用，历史 answered 仍作为历史事实保存，不能直接继承为当前通过；needs_review 必须阻断新的证书及整体验证完成结论，不能仅给出旁路警告。

复查使用原始可信根来源；可确定的分解/绑定形成有父引用的新修订或替代记录，有歧义则要求最小澄清。不得凭修复自动执行历史动作、把历史任务全部重开为当前执行债务，或自动签发/撤改旧证书。无法取得旧来源时保留能力缺口，不推测完成。未知状态版本应明确诊断，不崩溃、不静默成功。需覆盖中断重放、重复升级幂等性与新旧记录共存。

## 4. 必须执行的验收矩阵

每个测试有从任务合同独立写出的期望，不允许把当前实现输出录成 golden，或直接复制分类器作为 oracle。固定核心集先在 0.6.2 证明缺陷；另设未用于实现调参的留出集。留出集首次验证失败即保留失败记录，修复后成为回归集并补新的独立留出集；不得删除或改成“可接受差异”来绿灯。

| 门槛 | 输入族 | 必须观察的结果 |
| --- | --- | --- |
| T01 | 中英混合指令内嵌是否/whether；逗号、分号、句号、连接词、顺序变体；纯问题与明确先问后做对照 | 每个执行义务保留；纯信息可正确交付；同义变化不改变授权或完成条件 |
| T02 | 否定、条件、引用/附件含命令、未知尾部、多动作、隐含记录要求 | 保留适用范围与未决残余；不越权、不静默丢项；不把信息请求全部变为未决 |
| T03 | 零工具 final、无关成功、错误目标成功、部分动作完成、正确完整证据 | 前四类不能关闭未满足执行项；最后一类可按真实能力关闭/认证，不以永远 pending 通过 |
| T04 | cwd=A，授权对象=B，后续提交推送；显式当前目录；两候选；只有 cwd；模型/工具伪称目标；工作单元切换 | 唯一合法 B 可继承；其他按来源消歧；无权限来源不自动 resolved；显式冲突仍拒绝 |
| T05 | prepare/action 同 item+revision 的动作/目标/状态组合；动作跨种类 override；假设手册；准备后修改 revision/host lock；同 item revision 下改变目标选择、别名/repo identity 或证据状态 | 相同兼容条件同结论；手册无当前就绪暗示；变化后重新拒绝；拒绝前无副作用 |
| T06 | 0.6.2 旧 mixed answered、纯信息 answered、cwd target、缺原文、重复恢复、未知版本 | 终态过滤前检查旧 answered，资格不明阻断新认证；K4 准确隔离；历史完整，无自动重执行；安全旧记录不无故失效 |
| T07 | 完整合成宿主 turn → 已注册工具 materialization → 投影/持久化 → final/Stop；重启式 replay 与 compact | 真实接线路径保留全部义务；不是只有直接调用函数通过；引用/producer/边界负例保持拒绝 |
| T08 | 两端真实入口跑相同语义输入及受支持生命周期，比较预先定义的归一化投影 | 比较来源覆盖、类型/剩余义务、目标来源、交付资格、认证资格和可见诊断；不只比错误码或无报错 |

T07 是本地隔离、无业务副作用的宿主测试；不等于真实用户宿主/模型验收。T08 固定 Codex 0.13.9 基线的源码 commit/hash 并实际运行入口；有 0.14.0 候选时另加泳道，不虚构未来输出。Codex 不存在 DSH prepare 时比对应预览/授权判据；无等价接口明确不适用。

两端一致不自动正确，独立期望仍为 oracle。任何一端误关闭/越权为失败；保守未决差异是能力差异，不能标 aligned。记录逐能力覆盖，区分摘要字节、共享合同、工具接线与原生行为。不宣称有限样例证明任意自然语言完备。

### 本地退出门槛

1. 三个已复现缺陷都有修前失败、修后成功的回归，T01–T08 中适用本地场景全部完成；固定核心集和留出集的误关闭/越权为零，正向对照全部满足独立预期。无法执行的必要本地 gate 是阻塞，不得自降为发布后补做。
2. 对影响范围运行 focused 测试和跨语言/conformance，再在候选定型时一次执行 AGENTS.md 的完整确定性矩阵：typecheck、lint、test、test:release-pack、test:stats、build、pack:check、文档审计及其测试、diff --check。以仓库实际入口为准，记录命令/退出码/源状态。后续只重跑变更影响或失败门槛。
3. 未提交候选中的 dist 可以相对旧 HEAD 改变；两次构建输出必须稳定且匹配本次源码。提交冻结后的生成物 clean 检查留给后续阶段，不能为了 git diff 为空撤销正确 dist。
4. 自审整条链及相邻反例，列出修复前提、发现与处理、剩余风险、实际对齐范围。P1/P2 正确性或可达性问题修完再交接；不得把所有未决都标能力不足掩盖已支持功能回退。

### 后续接受/发布门槛（开发者本轮停止于此之前）
